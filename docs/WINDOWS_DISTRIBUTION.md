# MORS AEGIS Windows distribution

The launcher source is `launcher/Program.cs`. Build on Windows with .NET SDK 10 and a standalone Node 26 executable: `pwsh -File scripts/build-windows.ps1`. The script restores required .NET runtime packs from nuget.org, creates `MORS-AEGIS-Windows` beside this repository and fails if that destination already exists. Use `-Destination <new path>` for another build.

The build copies only application code/data, the Node runtime with its bundled license, and `mors.exe`; local `.env`, credentials, tests, reports and Git metadata are excluded. It does not put API keys into the binary or distribution. The launcher binds the backend to the private LAN on a port in `4173–4200`, requires an access token for browser and API access, verifies `/api/health` and `/api/catalog`, opens the default browser, and stays in the Windows system tray. The first launch generates a random access token at `%LOCALAPPDATA%\MORS-AEGIS\lan-access.token`. Right-click the tray icon and choose **LAN access details** to see the current private IP address and token to enter on another trusted device. The launcher attempts to add a Windows Firewall rule scoped to the Private profile, local subnet, executable, and selected port; Windows may ask for administrator approval. If firewall setup is declined or fails, allow `mors.exe` on Private networks or create an equivalent scoped inbound rule. Double-click the tray icon to reopen the app; right-click and choose Exit to stop its child backend. A second launch opens the running instance. Logs contain launcher status only at `%LOCALAPPDATA%\MORS-AEGIS\launcher.log` and are rotated at 1 MB. The database is written to `%LOCALAPPDATA%\MORS-AEGIS\data\mors.sqlite`.

This is intended for a trusted private LAN. The app uses HTTP, so the access token and session are not encrypted in transit; do not expose the port to the public internet or use an untrusted network. Other devices need a browser and network access to the host PC. The address may change when the host reconnects to Wi-Fi; reopen LAN access details to check it. The packaged app and its data are portable across Windows PCs, but each PC keeps its own local database and credentials.

`mors.exe --self-test` starts the bundled backend, checks readiness, then stops without opening a browser or creating a firewall rule. Inspect its process exit code and the launcher log. This verifies the packaged backend on the build machine; access from a physically separate LAN device and a clean-machine Windows test should be confirmed after download. The launcher currently terminates its child process on Exit; no in-flight request draining is implemented. Database integrity uses SQLite's built-in checks from the scientific data layer where available.
